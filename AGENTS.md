# Инструкции для AI-агентов

## Назначение

Этот файл содержит правила работы с проектом Mordheim Campaign Manager.

## Архитектура

- Проект строится как модульный монолит.
- Не добавлять микросервисы без явного согласования.
- Соблюдать существующие границы модулей и минимизировать связанность между ними.

## Backend

- Бизнес-логика должна находиться в сервисах, а не в API-обработчиках.
- API-обработчики отвечают за транспортный слой: валидацию входных данных, вызов сервисов и формирование ответа.
- Не дублировать бизнес-правила между обработчиками.

## Безопасность

- Не хранить секреты, токены, ключи и пароли в Git.
- Использовать переменные окружения или другие предусмотренные проектом безопасные хранилища.
- Пароли хранить только в виде стойких хешей; не сохранять их в открытом виде.
- Не добавлять чувствительные данные в логи, тестовые фикстуры и сообщения об ошибках.

## Общие правила

- Перед изменением файлов изучать существующую структуру проекта и локальные инструкции.
- Не изменять файлы, не относящиеся к текущей задаче.
- Сохранять текущий стиль кода и форматирование.
- Не удалять и не перезаписывать пользовательские изменения без явного разрешения.
- Для новых зависимостей сначала проверять, действительно ли они необходимы.
- Не создавать дополнительные файлы без необходимости.

## Рабочий процесс

1. Понять задачу и найти затрагиваемые файлы.
2. Просмотреть соответствующий код и существующие тесты.
3. Внести минимальные изменения.
4. Для новой бизнес-логики добавить или обновить тесты.
5. Запустить подходящие проверки и тесты.
6. В итоговом сообщении указать изменённые файлы и результаты проверок.

## Тесты

- Добавлять тесты для новой бизнес-логики.
- При изменении существующей логики обновлять затрагиваемые тесты.
- Использовать тестовые практики и инструменты, принятые в проекте.
- Если проверку невозможно выполнить, явно указать причину.

## Git

- Не выполнять `reset --hard`, `checkout`, удаление веток или другие разрушительные операции без явного разрешения.
- Не создавать коммиты без отдельной просьбы.
- Не изменять историю Git.
